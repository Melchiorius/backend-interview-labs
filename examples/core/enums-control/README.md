# CORE-ENUMS + CORE-CONTROL — общий Java 21 runnable

Пакет дополняет две самостоятельные статьи:

- [CORE-ENUMS](../../../knowledge/01-java-core/enums.md) — перечисления как закрытые типы с именованными экземплярами, identity, конструкторами, поведением, EnumSet и EnumMap.
- [CORE-CONTROL](../../../knowledge/01-java-core/control-flow.md) — условия, циклы, метки, switch statement, switch expression и yield.

Исходники основаны на полных положительных программах принятого исследовательского плана G1, §7. В B4b исправлено техническое форматирование enum: вместо преобразования регистра с локалью по умолчанию используется Locale.ROOT; оба эталона сохранены. Они показывают совместную работу enum и `switch`, но не заменяют теорию и не превращают наблюдения в независимые модульные тесты.

## Состав пакета

| Файл | Назначение |
|---|---|
| [src/EnumProbe.java](src/EnumProbe.java) | Программа E01–E30 на основе G1 с исправлением B4b; 30 подписанных строк stdout. |
| [src/ControlProbe.java](src/ControlProbe.java) | Полная программа G1 C01–C21; 21 подписанная строка stdout. |

| [verify.sh](verify.sh) | Компиляция, два отдельных запуска JVM и два строгих сравнения diff -u. |

**30 + 21 = 51 наблюдение в выводе двух JVM-процессов, а не 51 JUnit-тест.** Пакет не требует Gradle, JUnit, Mockito или сетевого доступа; нужна установленная JDK 21.

## Запуск

Из корня репозитория на Linux/macOS или в Git Bash:

~~~bash
bash examples/core/enums-control/verify.sh
~~~

Скрипт использует javac --release 21 -Xlint:all, собирает class-файлы во временный каталог mktemp, удаляет его через trap, запускает EnumProbe и ControlProbe в отдельных JVM-процессах и сравнивает полный stdout каждого процесса с соответствующим эталоном. Скрипт завершается ошибкой при любом предупреждении/диагностике javac, stderr JVM или несовпадении stdout.

Ожидаемый результат:

~~~text
CORE-ENUMS + CORE-CONTROL: PASS (30 + 21 stdout lines; 2 JVM processes)
~~~

## Что наблюдать

### EnumProbe

- E01–E04: порядок values(), name(), ordinal() и переопределённый toString() — разные контракты; ordinal() не является бизнес-идентификатором.
- E05–E10: valueOf, явный business code 67, разрешённый переход состояния и поведение констант, реализующих интерфейс.
- E11–E14: итерация по элементам EnumSet и ключам EnumMap идёт в порядке объявления enum; EnumMap допускает null как значение и сохраняет различие между отсутствующим ключом и ключом с null.
- E15–E19, E28–E29: EnumSet.add(null) и EnumMap.put(null, ...) бросают NullPointerException, тогда как contains(null)/remove(null) у EnumSet и containsKey(null) у EnumMap возвращают false; valueOf различает неизвестное имя и null.
- E20: каждая enum-константа — единственный экземпляр соответствующего значения в рамках загрузки её типа, но внутри неё могут быть изменяемые поля; это само по себе не обеспечивает неизменяемости или потокобезопасности.
- E21–E24: у константы с собственным телом класса `getClass()` отличается от `getDeclaringClass()`; `Class.isSealed()` показывает различие между обычным enum и enum с телом класса конкретной константы.
- E25–E27, E30: identity enum, допустимость квалифицированной enum-константы в Java 21 switch, независимость массива, возвращённого values(), от последующего вызова и различие name()/toString().

### ControlProbe

- C01–C02: else относится к ближайшему незавершённому if.
- C03–C06: классический switch допускает fall-through и отсутствие default; arrow rule не проваливается в следующую ветку.
- C07–C08, C16: switch expression должен дать значение; yield возвращает результат из блока или colon-группы.
- C09, C17, C20: break/continue, включая метку внешнего цикла, управляют разными областями выполнения.
- C10–C12: while проверяет условие до тела, do/while — после, enhanced for проходит элементы коллекции.
- C13, C21: && и || вычисляют правый операнд только при необходимости.
- C14–C15: Java 21 допускает case null в данном switch; без такой ветки null-selector вызывает runtime NullPointerException.
- C18: изменение локальной переменной enhanced-for не заменяет элементы массива.
- C19: selector switch вычисляется один раз.

## B4b — нейтральное техническое форматирование

В программе `EnumProbe` строка E01 получается при вызове `Arrays.toString(Status.values())`: метод `values()` возвращает массив констант в порядке объявления, а `Arrays.toString()` формирует строковое представление массива, вызывая `toString()` каждого его элемента. В перечислении `Status` этот метод переопределён и использует выражение `"status-" + name().toLowerCase(Locale.ROOT)`. Ожидаемая строка:

~~~text
E01=[status-new, status-paid, status-sent, status-done]
~~~

Метод [`name()`](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Enum.html#name()) возвращает точное имя из текущего объявления. В отличие от него, `toString()` можно переопределить. Метод `valueOf()` ищет константу по имени, а не по её строковому представлению. В E04 отдельно вызывается `Status.NEW.toString()`; этот вызов даёт `status-new` и не выявляет проблему с локалью.

Метод [`toLowerCase()`](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/String.html#toLowerCase()) без параметров использует локаль по умолчанию. При `tr_TR` слово `PAID` преобразуется в `paıd`: вместо обычной строчной i (U+0069) получается строчная i без точки (U+0131). В исходной версии это меняет только представление `PAID` внутри E01. Различие вызвано правилами преобразования регистра, а не кодировкой вывода. Явная [`Locale.ROOT`](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/util/Locale.html#ROOT) в [`toLowerCase(Locale)`](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/String.html#toLowerCase(java.util.Locale)) подходит для нейтрального технического формата. Для текста, предназначенного человеку, локаль выбирают с учётом языка пользователя. Ни `ordinal()`, ни переопределённый `toString()` сами по себе не обеспечивают стабильность бизнес-идентификатора: для явного кода или отдельного сопоставления нужен контракт уникальности и совместимости. Ни программа, ни проверочный скрипт не меняют и не фиксируют локаль по умолчанию.

Историческое наблюдение и исходный вариант G1 зафиксированы в [A17.2](https://github.com/Melchiorius/backend-interview-labs/blob/3f5648eddc98f0308328224d840e9d3933c6bb3a/docs/audits/java-core-full-2026-11-24/A17.2-CORE-CONTROL.md#L71-L72); [согласованный контракт B4b](https://github.com/Melchiorius/backend-interview-labs/issues/289#issuecomment-7163012185) сохраняет оба эталона, `ControlProbe` и проверочный скрипт. Исторические планы и материалы аудита не изменены.

**Фактическая локальная проверка роли 03.** [Отчёт о шести полных запусках скрипта и отдельных измерениях](https://github.com/Melchiorius/backend-interview-labs/pull/290#issuecomment-7163131359) по [задаче #289](https://github.com/Melchiorius/backend-interview-labs/issues/289) относится к первоначально проверенной технической версии `40c177925e8babfb14ed204bda21cdf76767ec55`. Исходную и исправленную версии проверили на Debian с OpenJDK/javac 21.0.12.1 при `LC_ALL=C`.

Для каждого режима испытания временную исполняемую обёртку команды `java` помещали первой в `PATH`. Она вызывала один и тот же исполняемый файл `/usr/lib/jvm/java-21-openjdk-amd64/bin/java` по абсолютному пути, добавляя параметры JVM перед остальными аргументами. Во всех случаях задавали `-Dstdout.encoding=UTF-8`. Для режима по умолчанию других параметров локали не было; для `en_US` дополнительно задавали `-Duser.language=en -Duser.country=US`, для `tr_TR` — `-Duser.language=tr -Duser.country=TR`. Переменные `JAVA_TOOL_OPTIONS`, `JDK_JAVA_OPTIONS` и `_JAVA_OPTIONS` были сняты. Обёртки находились вне репозитория.

Отдельная программа, запущенная через те же обёртки, подтвердила фактические значения `Locale.getDefault()`: `en_US`, `en_US`, `tr_TR`; значения `user.language` и `user.country` — соответственно `en/US`, `en/US`, `tr/TR`. Во всех трёх режимах `System.out.charset()`, `stdout.encoding`, `file.encoding` и `Charset.defaultCharset()` соответствовали `UTF-8`, а `native.encoding` — `ANSI_X3.4-1968`. Это три конфигурации JVM, а не проверка системных локалей разных ОС.

| Конфигурация JVM | Исходный скрипт: код завершения | Исправленный скрипт: код завершения |
|---|---|---|
| По умолчанию (фактически `en_US`) | 0 | 0 |
| `en_US` | 0 | 0 |
| `tr_TR` | 1 (E01: `status-paıd`) | 0 |

Во всех шести запусках поток ошибок скрипта (`stderr`) был пуст. В исходной версии при `tr_TR` оба процесса JVM уже завершились, когда первое сравнение командой `diff -u` обнаружило расхождение в E01. Скрипт завершился с кодом 1, поэтому второе сравнение, с эталоном вывода `ControlProbe`, не состоялось; маркер успеха не напечатан. В исправленной версии все три запуска завершились с кодом 0 и напечатали исходный маркер `CORE-ENUMS + CORE-CONTROL: PASS (30 + 21 stdout lines; 2 JVM processes)` после обоих строгих сравнений.

**Отдельные прямые запуски.** Скрипт создаёт временный каталог и удаляет его при завершении через `trap`. Чтобы сохранить полный вывод обеих программ, для каждой из двух версий отдельно выполнили совместную компиляцию `EnumProbe.java` и `ControlProbe.java` командой `javac --release 21 -Xlint:all` с указанием каталога для классов. Обе компиляции завершились с кодом 0 без вывода и диагностических сообщений. Затем каждую программу запустили в каждой из трёх конфигураций JVM. Все 12 отдельных запусков завершились с кодом 0, потоки ошибок были пусты. Полный вывод получен именно в этих запусках, а не извлечён из временных файлов скрипта или логов CI.

Во всех шести парах запусков `ControlProbe` напечатал ровно 21 строку, побайтно совпадающую с эталоном. В исходной версии `EnumProbe` напечатал 30 строк; сравнение выявило единственное расхождение в E01 при `tr_TR`. В исправленной версии все 30 строк `EnumProbe` и 21 строка `ControlProbe` совпали побайтно с соответствующими эталонами и между тремя конфигурациями. Остальные 29 строк E и все 21 строка C сохранились при сравнении исходной и исправленной версий. Это наблюдения в выводе программ, а не 51 независимый тест. Команда `bash examples/core/enums-control/verify.sh` из корня репозитория без обёрток и параметров локали также завершилась успешно, с исходным маркером и пустым потоком ошибок.

Оба эталона и `ControlProbe.java` сохранены побайтно, скрипт сохранил содержимое и режим `100755`. При последующих правках только README все пять проверенных файлов сохранили хэши и режимы относительно первоначально проверенной технической версии. Повторных запусков Java из-за этих редакционных правок не было. Проверки не доказывают универсальную переносимость на все локали, ОС и версии JDK.

## Границы проверки

Скрипт проверяет две положительные программы и точное совпадение вывода на установленной JDK 21. Исследовательские отрицательные примеры компиляции N01–N26/N28–N32 из G1 §8 намеренно не входят в обычный скрипт/CI. Скрипт не подтверждает поведение других JDK/JVM/ОС, JMM, бинарную эволюцию enum, JPMS, JIT/GC, производительность или результаты измерений.
