Каждый документ содержит **самодостаточный текст для запуска нового чата** и короткую справку о входах, результатах и границах роли. Скопируйте раздел «Текст для запуска нового чата» в отдельный чат. Само по себе создание чата не выдаёт полномочий GitHub — для действий нужен доступ к соответствующим инструментам/репозиторию.

## Актуальная версия и автоматизация

Организационный PR #21 уже объединён. Стартовые инструкции следует читать из актуального `main`, а при проверке изменений — из рабочей ветки соответствующего PR. **Сведения о первых поручениях являются историческим примером**, не поводом повторно открывать завершённые Issues/PR.

Для всех семи чатов действует [протокол передачи задач](../ROLE_HANDOFF_PROTOCOL.md). При завершении задачи роль оставляет отчёт и структурированный `backend-handoff` в **GitHub Issue**; [Python-диспетчер](../../tools/role_dispatcher.py) проверяет машинно подтверждаемые условия, создаёт inbox-файлы и при `--publish` — адресные комментарии в Issue. Это **не автоматически запускает чат ChatGPT**, и GitHub-доставка не заменяет G4 review.

Перед действиями каждая роль **обязательно повторно проверяет актуальные GitHub `main`, Issue/PR и HEAD SHA**, вместо механического исполнения исторического «первого поручения», которое могло уже быть завершено.

Общие требования не копируются в эти файлы: первичны [AGENTS.md](../../AGENTS.md), [ROLE_MODEL.md](../ROLE_MODEL.md), [WORKFLOW.md](../WORKFLOW.md), [CURRICULUM.md](../CURRICULUM.md) и [COVERAGE.md](../COVERAGE.md). При конфликте роль должна зафиксировать разночтение и передать его 00/06, а не молча выбирать удобный стандарт.

Для новой задачи используйте актуальные Issue и решения 00, а не воспроизводите завершённые этапы 2026-11-19.
