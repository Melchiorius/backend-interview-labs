Само по себе создание чата не выдаёт полномочий GitHub — для действий нужен доступ к соответствующим инструментам/репозиторию.

## Общий обязательный протокол эстафеты

**Каждый новый и уже работающий чат роли 00–06** должен соблюдать [правило из AGENTS](../../AGENTS.md#обязательная-передача-эстафеты-между-ролями-0006): заканчивать рабочий отчёт в GitHub явным блоком **«Передача эстафеты»** (`Кому: NN`, `Что сделать`, `Передать`), а после публикации выдавать оператору готовую прямую ссылку на конкретный комментарий. При отсутствии следующего исполнителя — `Кому: никому` с причиной. Это правило продублировано **внутри текста для запуска каждого чата** ниже; подробная форма — в [WORKFLOW.md](../WORKFLOW.md). Его нужно применять в текущем чате, не ожидая его перезапуска. **Завершена тема — эстафета обязательно идёт 00 на следующую тему:** после G6 роль 06 передаёт 00 прямую ссылку на отчёт с требованием запустить следующий G1 или подтвердить уже запущенный; 00 не оставляет программу без нового назначения. Исследование следующей темы разрешено начать после G5 параллельно G6.

## Проверка актуальности при запуске нового чата

Все инструкции следует читать из актуального `main`. **Исторический Issue, PR или пример темы в документации не становится новым поручением автоматически.** При старте роли нужно сверить открытые Issues/PR, их HEAD и текущий gate, после чего принять конкретное адресное задание. Если следующая задача неизвестна, передайте предметный вопрос координатору 00, а не выбирайте следующую исследовательскую тему без назначения.
