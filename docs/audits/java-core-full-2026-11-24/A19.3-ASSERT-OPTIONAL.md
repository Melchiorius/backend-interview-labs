## 2. N03 normative/implementation boundary — additional targeted evidence

Re-opened [JLS21 §14.10](https://docs.oracle.com/javase/specs/jls/se21/html/jls-14.html#jls-14.10), L544–575,576–605; it says an assertion executed before its class/interface completes initialization is enabled, gives the cyclic hierarchy example and distinguishes enabled/disabled evaluation. This wording was accurately reported by the article. A19.1 recorded cyclic result true/false under -da and direct static initializer false under -da. Do not rewrite the rule as a new universal guarantee based on observed javac behavior.

Actual additional local inspection 24.11.2026, same Debian OpenJDK 21.0.12.1, preserved /tmp/a19-assert sources and classes. Command `javap -p -c -classpath out Direct Baz Bar` exit0, and `java -da -cp out Direct`, `java -da -cp out Foo` exit0; output direct=false and cyclic=true then cyclic=false. Direct.java uses a local boolean initialized false in its static block, assert enabled=true, then print. Foo.java uses Baz extends Bar with Bar static block calling Baz.testAsserts() while Baz initialization in progress, and main calls it again.

- Direct.<clinit> offsets 0–13 compute negated Class.desiredAssertionStatus and putstatic synthetic boolean $assertionsDisabled before user code; offsets 18–21 read and branch around assert. This explains why the ordinary direct initializer observes false under -da on this compiler.
- Baz.testAsserts offsets 2–5 read the synthetic field; Baz.<clinit> offsets 0–13 assign it from policy. Bar.<clinit> offset 0 invokes Baz.testAsserts before that assignment, while boolean field still has default false; after initialization the field is true under -da. Explains recorded cyclic true/false. The mechanism is an observation of generated bytecode for these two classes, not mandated lowering or proof about all JDKs.
- Searched for direct-initializer/JLS discrepancy and a matching OpenJDK issue; no confirmed primary issue resolving this exact discrepancy found in retrieved results. Older Java6 wording and unrelated outer-class initialization discussion are not resolution for Java21. No pinned OpenJDK compiler implementation source claimed. Keep N03 P1 and unresolved normative-vs-observed boundary; acceptance: give normative example, distinguish observed ordinary initializer behavior and mark limits, do not claim spec corrected or implementation bug established. No new BLOCKER or ERROR for faithful quotation. This targeted rerun/bytecode inspection is new evidence; full package runner and original negatives not repeated.
