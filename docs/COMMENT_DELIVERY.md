# Передача адресов GitHub-комментариев между чатами 00–06

**Назначение:** вспомогательный Windows-диспетчер пересылает **только URL нового обычного комментария GitHub**, а не его текст. GitHub Issue/PR остаётся единственным источником поручений. Это **не** новый gate, review, workflow или система подтверждения работы.

## Формат исходящего сообщения

Откройте назначенный Issue либо PR и создайте **новый обычный комментарий** (Issue comment / PR conversation comment):

~~~text
Кому: 02

Подготовить статью CORE-INIT по Issue #51 и принятому исследовательскому плану PR #50.
Сверить её с уже готовым примером PR #53; указать реальные проверки и новый HEAD.
~~~

- **Ровно один адресат**: `Кому: 00` … `Кому: 06` отдельной строкой в первых 12 строках, допускаются жирное Markdown или заголовок. Для двух ролей — **два отдельных комментария**, каждый с содержательным поручением. Не нужно оформлять JSON, `backend-handoff`, `event_id`, `gate`, `action`, `requires`, дополнительное копирование поручения или ссылку внутри самого комментария.
- Остальной текст абсолютно свободный: ссылки на Issue/PR, критерии, ограничения, SHA и результаты проверок сохраняются в той полноте, **которую требует задача и существующий WORKFLOW**. Изменяется только способ доставки, **не содержание и не критерии G0–G6**.
- Если роль завершила работу и **действительно нужно следующее действие другой роли**, она создаёт адресный комментарий. Если адресата/нового задания нет — не создавать фиктивного сообщения. Reviewer оставляет обычный полноценный review в PR, а для маршрутизации при необходимости — короткий адресный **обычный комментарий** с прямой ссылкой на review; inline review не опрашивается.
- Любой новый комментарий получает **GitHub comment ID** и постоянный URL. При изменении уже переданного поручения публикуйте новый комментарий: редактирование старого ID не приводит к повторной доставке.

## Работа диспетчера

Из корня локальной копии репозитория в PowerShell:

~~~powershell
$env:GITHUB_TOKEN = "<fine-grained GitHub token with read access>"
# На первой установке: НЕ рассылать старую историю
py tools/comment_mailman.py --bootstrap
# Проверить следующую доставку без переключения вкладок и изменения SQLite
py tools/comment_mailman.py --dry-run
# Обычный цикл: один URL на опрос, пауза 120 секунд
py tools/comment_mailman.py --interval 120
~~~

По умолчанию читаются **три последние страницы по 100 комментариев** репозитория `Melchiorius/backend-interview-labs`. Флаг `--pages 5` увеличивает глубину; `--repo OWNER/REPO` и `--actor LOGIN` — опции. При длинном простое и более 300 новых комментариях прежде чем ждать уведомлений задайте больше страниц. **Не используйте `--bootstrap` повторно**, если хотите доставить уже накопившиеся новые поручения.

Диспетчер получает комментарии через официальный REST endpoint **issues/comments** (он включает обычные комментарии и к Issue, и к PR). Для безопасности учитывает только комментарии GitHub-владельца репозитория и дополнительно указанных `--actor`. Учитывает **только** `Кому: NN` в первых 12 строках и проверяет постоянную ссылку. Гейт-статусы, CI, HEAD, содержание поручения и корректность решений остаются ответственностью ролей.

Схема вкладок — фиксированная: `00 → 1`, `01 → 2`, `02 → 3`, `03 → 4`, `04 → 5`, `05 → 6`, `06 → 7`. Нужен **ровно один видимый Firefox window** с семью чатами в указанном порядке. Windows может запретить фоновой программе активировать Firefox: тогда событие **не записывается как обработанное**, будет повторено в следующем цикле. При блокировке OpenClipboard — аналогично.

SQLite: `.comment-mailman/seen.sqlite3`, **единственная таблица** `seen(comment_id INTEGER PRIMARY KEY)`. ID записывается **после** успешного переключения окна/вкладки и копирования URL в буфер. Обрабатывается **не более одного** нового поручения за цикл. Вставка в ChatGPT (`Ctrl+V` или `Shift+Insert`) и отправка (`Enter`) — **только вручную**; `PREPARED` не доказывает, что пользователь вставил и отправил ссылку. Следующий опрос может заменить буфер, поэтому заранее вставьте текущее сообщение. Ссылка открывает оригинальный GitHub-комментарий, и чат с GitHub-доступом читает его непосредственно там.

**Не поддерживается:** автоматическое чтение/отправка ChatGPT, синхронизация ответов, автоматический merge, inline PR code review и отдельные GitHub review submissions, восстановление изменённых комментариев с прежним ID, гарантированное переключение окна вопреки правилам Windows. Скрипт вообще не пишет в GitHub. Не храните токен в репозитории; на компьютере он доступен только через переменную окружения.

Рекомендуемая независимая проверка без сети и Windows:

~~~powershell
py -m unittest discover -s tools/tests -p 'test_comment_mailman.py' -v
~~~
