# Принципы самостоятельной работы с базой знаний

Это **документ для автора материалов**, а не инструкции по обязательному маршруту обучения. Читатель выбирает тему, порядок и глубину самостоятельно.

## Простой цикл использования
1. Открыть нужную Markdown-статью в GitHub или Obsidian.
2. Прочитать точные определения и краткое объяснение принципа; разобрать схему, если она есть.
3. Перейти по ссылке к полному запускаемому примеру Java.
4. Открыть задачу с заготовкой, внести своё решение и запустить тесты **только этой задачи**.
5. Посмотреть на результат, вернуться к статье, изучить более глубокий раздел или перейти к другой теме.

Ни регистрация, ни сохранение прогресса, ни обязательные этапы обучения, ни преподаватель для этого не требуются.

## Требования к содержанию
- Текст конкретный, связный и экономный; ни «простыней», ни телеграфных списков терминов без причинных связей.
- Каждый термин объяснить при первом использовании или дать прямую ссылку на определение.
- Приоритет — принцип работы, устройство, инварианты, контракт, мотивация конструкции и границы применимости.
- Когда схема яснее прозы — использовать схему с подписями. Не заменять точные детали декоративными картинками.
- Короткие демонстрационные фрагменты оставить в Markdown, а полные программы — в .java-файлах с рабочими тестами.
- Углубления Middle+/Senior располагаются отдельно и необязательны. Не переоценивать уровень общеупотребимых технологий.
- Практика — средство проверки кода, а не аттестация пользователя. Можно читать без решения задач.
- Для утверждений о Java различать JLS, JVMS, API и детали конкретной JVM; ориентир — Java 21.

## Минимальная самостоятельность
У каждой статьи есть определение и логичный переход к следующей связанной информации. У каждой задачи: входной контракт, ожидаемое поведение, ограничения, место для решения, команда запуска тестов и диагностируемые результаты. При наличии эталона указать его расположение без навязывания порядка просмотра.

## Проверка качества перед PR
1. Можно ли понять идею за одно чтение без внешнего рассказчика?
2. Можно ли убрать предложение без потери существенного смысла? Если да — удалить.
3. Для схемы есть ли объяснение обозначений, соответствует ли она фактическому алгоритму?
4. Можно ли выполнить код/тесты на чистой машине с описанными предпосылками?
5. Работают ли ссылки между теорией, примером, упражнением и обратно?
6. Не смешали ли обычные знания уровня Middle с факультативными специализированными нюансами?
