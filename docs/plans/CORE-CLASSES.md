# CORE-CLASSES — план исследования до написания статьи

**Статус:** исследовательская карта темы, составлена до текста статьи. **Java:** JLS 21, учебные исходники на Java 21. **Дата:** 2026-11-19.

## Обещание, границы и требования

**Обещание читателю:** после статьи самостоятельно объяснять разницу между классом и объектом; поля, методы, конструкторы и `this`; статические и экземплярные члены; создание и допустимое состояние объекта; типичные вопросы `new`, `static`, `default constructor`, `constructor overloading`, `initialization`.

**Границы:** базовые понятия наследования, видимости и инициализации кратко вводим для объяснения, но полноценное рассмотрение — отдельные `CORE-ACCESS`, `CORE-INIT`, `CORE-INHERITANCE`, `CORE-INTERFACES`; `equals/hashCode` — `CORE-OBJECT`/`CORE-EQUALITY`; `ClassLoader` — `JVM-LOADING`; безопасность разделяемого состояния — `CON-RACE` и `CON-JMM`. Не писать «все классы/объекты лежат в такой-то области памяти»: это зависит от реализации.

- **Официальные объяснения B:** [dev.java Classes and Objects](https://dev.java/learn/language/oop/classes-objects/), [dev.java More on Classes](https://dev.java/learn/language/oop/classes-objects/more-on-classes/).
- **Независимые кандидаты вопросов C:** [Baeldung Class Structure and Initialization Interview Questions](https://www.baeldung.com/java-classes-initialization-questions), [Java Classes & Objects interview topics](https://interview-prep.coderboi.com/java/oop/classes-objects), [общий банк Java Core](https://github.com/teamlead/java-interview-questions) из [SOURCE_REGISTRY](../SOURCE_REGISTRY.md). Два последних служат кандидатами тем; **не** нормативным обоснованием. Авторские ответы могут быть ошибочными/устаревшими и не заменяют JLS.

## Код, проверка и будущие ссылки

- Короткие фрагменты **в статье**: два независимых объекта, alias, default constructor, перегрузка `this(...)`, `static` vs instance, shadowing и локальные ошибки компиляции.
- Один **самостоятельный Java 21 пример**: небольшой класс `CreditAccount` с положительным пополнением, запретом перерасхода и инвариантом неотрицательного остатка; общее `static` число созданных экземпляров; второй объект и alias; проверка ошибочных случаев; запуск через `java examples/core/ClassesAndObjectsDemo.java`. Отдельное упражнение пока не создаём: сначала обучающее объяснение.
- **Действующие ссылки**: [CORE-TYPES](../../knowledge/01-java-core/types.md), [CORE-CONVERSIONS](../../knowledge/01-java-core/conversions.md), [CORE-PARAMS](../../knowledge/01-java-core/parameters.md), [реестр источников](../SOURCE_REGISTRY.md). **Пока только ID:** CORE-ACCESS, CORE-INIT, CORE-INHERITANCE, CORE-OBJECT, CORE-IMMUTABLE, CORE-COMPOSITION, JVM-LOADING, CON-RACE, CON-JMM.
- **Проверка полноты после написания:** для всех P0 есть объяснение и контрпример в статье, фрагменты Java компилируются там, где это предполагается; некомпилируемые строки помечены; CI проверяет рабочий пример, но не покрытие каждого вопроса. P1/P2 ясно разграничены.

## Остаточные риски

Не использовать «объект всегда в heap / локальная переменная всегда в stack» или «static одно для всего процесса» как общие гарантии. Избегать опасных демонстраций `this`-escape в конструкторе без объяснения и не называть успешную сборку доказательством исчерпывающего покрытия интервью-вопросов.
