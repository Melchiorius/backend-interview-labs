# Необязательный шаблон Markdown-статьи

**Назначение:** ориентир для автора. Это не форма из обязательных полей: оставлять только разделы, которые действительно помогают объяснить тему. Не делить материал на микростатьи.

# Название понятия

**Определение.** Что это такое; необходимые термины раскрыть здесь или дать работающие ссылки на статьи-предпосылки.

**Зачем нужно.** Конкретная задача и главная идея, без длинного вступления.

## Устройство и работа

Схема с обозначениями, если она яснее текста. Как устроена структура данных, какой инвариант у алгоритма, какую логику воплощает API/фреймворк, каков порядок действий, существенные гарантии и ограничения.

Короткий поясняющий Java-код — **прямо здесь**, если он укладывается в статью. Не создавать отдельный файл ради 5–10 строк.

## Пример или практика (если нужны)

Ссылка на **существующий** большой связный Java-пример или упражнение и конкретную команду запуска. Один пример может иллюстрировать несколько статей.

## Ошибки, альтернативы и глубина (по смыслу)

Только существенные контрпримеры/компромиссы. Дополнительную глубину можно разместить сразу **после основной идеи**:

```markdown
> [!note]- Дополнительно: необязательный нюанс
> Короткое углублённое объяснение.
```

В Obsidian это сворачиваемый callout, в GitHub может оказаться обычным блоком. Главная мысль **не должна** находиться только в нём. Не требовать формальных частей Middle/Middle+/Senior в каждой статье; ориентир уровня добавлять, когда он обоснован.

## Связанные статьи и источники

Ссылки на **реально существующие** Markdown-статьи, необходимые для понимания; по мере развития репозитория возвращаться к опубликованным материалам и добавлять связи. Указывайте первичные источники для версионных/спорных гарантий.

**Проверка:** после чтения без преподавателя понятны термин, механизм и границы; схемы точны; лишние абзацы отсутствуют; ссылки работают.
