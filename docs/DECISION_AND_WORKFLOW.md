# Правила принятия решений и обновления контекста

Назначение: инструкция для будущих сессий/ассистентов. Читать совместно с корневым [AGENTS.md](../AGENTS.md), [архитектурой курса](COURSE_ARCHITECTURE.md), [реестром](COVERAGE.md).

## Сначала задача и альтернатива
1. Определить конечную цель, проверяемый критерий успеха и обратимость изменений.
2. Сравнить путь ремонта, путь восстановления известного исправного состояния и отказ от ненужного изменения.
3. Оптимизировать **совокупные затраты за жизненный цикл**, не минимальную стоимость ближайшего шага. В фундаментальные исследования и гибкие границы стоит инвестировать заранее, но не реализовывать гипотетические механизмы без подтверждения потребности.
4. Разделять факты, гипотезы, риски и неизвестное; не делать алармистских выводов из единичной ошибки.
5. После двух безрезультатных попыток остановиться и пересмотреть модель отказа и стратегию; не повторять бесконечно настройки.
6. Предпочитать наблюдение и дискриминирующие тесты вмешательству; не превращать устранение локального сбоя в миграцию технологий без отдельного обоснования.
7. Восстановление/переустановка уместны, когда состояние воспроизводимо и ценные локальные изменения защищены; перед удалением обязательно проверять невоспроизводимые данные.
8. Не соглашаться автоматически с оператором и не защищать собственный первоначальный план: давать независимую, проверяемую оценку и менять курс при новых фактах.
9. Учитывать стоимость времени, когнитивной нагрузки и доверия; возможность «починить» не означает, что стоит чинить именно так.

## Зафиксированные уроки инцидентов
- При проблеме `Gradle Sync` CLI Gradle был исправен; в установке IntelliJ нечитаемым оказался `plugins/gradle/lib/gradle-api-8.8.jar` (CRC), переустановка IDE восстановила Sync. Урок: найти конкретный файл из stack trace прежде чем менять JDK/Wrapper/проект.
- Ограниченный Git refspec в локальном clone мешал отслеживанию `origin/main`. При отсутствии ценных локальных данных переименование каталога + clean clone часто дешевле многократного ручного ремонта. Не утверждать, что git был повреждён.
- Предупреждения Windows и CRC не дают основания предсказывать близкий отказ SSD без дополнительной диагностики.

## Контроль базы знаний (не учебная аналитика)
- У нового вопроса сначала найти место в [CURRICULUM](CURRICULUM.md) и показать имеющиеся справочные предпосылки, не навязывая очередность.
- Если тема пропущена (как Semaphore), внести в карту, реестр и план; не превращать последний вопрос интервью в единственный приоритет.
- Для темы сохранять links ↔ код ↔ упражнения ↔ тесты ↔ merge-задания.
- Не учитывать персональное **«освоено»** в репозитории. Отмечать полноту и качество материалов, примеров и тестов, включая глубину M/M+/S. Читатель сам выбирает траекторию и глубину.
- По завершении PR обновить [COVERAGE.md](COVERAGE.md): что реализовано, что проверено, что планируется, ссылки/команды и актуальные неизвестные.
- Не оставлять документацию со статусами, противоречащими реальному main.
