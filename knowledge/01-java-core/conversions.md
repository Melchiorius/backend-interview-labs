# CORE-CONVERSIONS — преобразования типов

**Java 21 · предпосылка:** [типы и значения](types.md)

Java может преобразовать значение одного типа в другой. Иногда это происходит автоматически, иногда требуется явное приведение. **Не всякое преобразование сохраняет исходное значение.**

## Расширение и сужение числового типа

```java
int count = 67;
long exact = count;            // int → long: значение 67 сохраняется
double approximate = exact;   // long → double: не все большие long точны

long large = 300;
byte narrowed = (byte) large; // 44: старшие биты отброшены
```

В последней строке приведение `(byte)` разрешено, но результат **не равен 300**. Явное приведение означает «разрешить преобразование», а не «гарантировать сохранение значения».

Преобразование `int → long` сохраняет все значения `int`. Однако переход `long → double` может потерять точность для больших целых чисел — `double` не хранит произвольные 64-битные целые точно.

## Почему арифметика с byte даёт int

```java
byte first = 40;
byte second = 27;
// byte sum = first + second; // ошибка компиляции
int sum = first + second;       // 67
```

Перед сложением `byte` и `short` обычно проходят **числовое продвижение** до `int`. Сам факт, что ответ помещается в `byte`, не меняет тип выражения.

`char` также участвует в числовых преобразованиях: это кодовая единица UTF-16, а не строка.

## Автоупаковка и распаковка

```java
Integer boxed = 67;       // int → Integer (boxing)
int restored = boxed;     // Integer → int (unboxing)

Integer missing = null;
// int result = missing;  // NullPointerException при распаковке
```

`Integer` — ссылочный тип: в отличие от `int` он может иметь значение `null`. Автоупаковка удобна для обобщённых коллекций, но не превращает тип-обёртку в примитив.

Не проверяйте числовое равенство объектов-обёрток через `==`:

```java
Integer a = 1000;
Integer b = 1000;
System.out.println(a == b);       // результат для таких значений не следует предполагать
System.out.println(a.equals(b));  // true
```

Для ссылочных переменных `==` сравнивает идентичность объектов. Реализация вправе повторно использовать объекты-обёртки в определённых случаях; поэтому **не привязывайте проверку числового равенства к результату `==`**. Для содержимого используйте `equals()` либо распакуйте значения с учётом возможного `null`.

## Как преобразования влияют на перегрузку

```java
static String choose(long value) { return "long"; }
static String choose(Integer value) { return "Integer"; }

System.out.println(choose(67)); // "long"
```

При выборе перегруженного метода компилятор использует правила применимости методов. В данном примере расширение примитивного `int → long` предпочтительнее упаковки `int → Integer` на соответствующей фазе выбора. Это не простое правило «выбрать ближайший тип»: существуют фазы выбора и другие случаи, например varargs.

## Когда возникает потеря информации

| Преобразование | Возможная проблема |
|---|---|
| `long → int` | Потеря старших битов |
| `double → int` | Отбрасывание дробной части и особенности обработки выхода за границы |
| `long → double` | Потеря точности больших целых чисел |
| `Integer → int` | `NullPointerException`, если ссылка равна `null` |
| Приведение ссылки к подтипу | `ClassCastException`, если объект несовместим |

> [!note]- Углубление: перегрузка и type inference
> Формальные правила выбора перегрузки определены в JLS. Нюансы generic overload, varargs, boxing и вывод типов относятся к будущим `CORE-GENERICS` и `CORE-ERASURE`. Достаточно помнить: результат зависит от типов выражений **на этапе компиляции**, а не от «того, какой объект удобнее».

> [!note]- Углубление: числовая точность
> В расчётах денег обычно нужен `BigDecimal` с осмысленными правилами округления. Ошибку `0.1 + 0.2` нельзя исправить произвольным `(double)`: она связана с представлением дробей. Продолжение — будущая `CORE-NUMBERS`.
