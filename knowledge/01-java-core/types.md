# CORE-TYPES — типы, значения и переменные в Java

**Java 21 · основа Java Core**

## Переменная хранит значение, а не «сам объект»

В Java каждая переменная имеет **тип** и хранит **значение**. Принципиально важно различать два случая:

- Для **примитивного типа** значение — само число, логическое значение или символ: например, `int count = 67`.
- Для **ссылочного типа** значение — ссылка на объект или `null`. Переменная типа `Account` не содержит поля объекта `Account` внутри себя.

Ссылка позволяет обращаться к объекту. Две переменные могут содержать ссылки на **один и тот же объект**.

```java
int a = 67;
int b = a;
b = 10;                     // a по-прежнему 67

StringBuilder first = new StringBuilder("A");
StringBuilder second = first;
second.append("B");          // first.toString() теперь "AB"
second = new StringBuilder("C"); // first всё ещё указывает на объект с "AB"
```

В первой паре переменных копируется число. Во второй — **значение ссылки**. Поэтому `append()` изменяет объект, доступный и через `first`, а присваивание новой ссылки переменной `second` не перенаправляет `first`.

**Не путать:** `==` для двух ссылок проверяет, ссылаются ли они на один объект (или обе равны `null`), а не совпадает ли содержимое объектов. Сравнение содержимого зависит от контракта `equals()` (будущая тема `CORE-EQUALITY`). Для типичного подвоха на собеседовании — [кэширования `Integer` и String Pool](conversions.md#похожий-вопрос-string-pool) — см. также соседнюю статью о преобразованиях.

## Восемь примитивных типов

| Типы | Что обозначают |
|---|---|
| `byte`, `short`, `int`, `long` | Целые числа фиксированной разрядности; арифметика может переполняться |
| `char` | 16-битная кодовая единица UTF-16, не обязательно целый символ Unicode |
| `float`, `double` | Числа с плавающей точкой; многие десятичные дроби представлены приближённо |
| `boolean` | `true` или `false` |

**`String` не примитив:** это класс. `null` не является отдельным примитивным значением; оно применимо к ссылочным типам.

## Тип переменной и тип объекта

```java
CharSequence value = new StringBuilder("text");
```

Здесь **объявленный тип переменной** — `CharSequence`, фактический объект — `StringBuilder`. Объявленный тип определяет, какие операции доступны через переменную на этапе компиляции; фактический класс объекта влияет на реализацию вызываемого метода. Полное объяснение — будущие `CORE-INTERFACES` и `CORE-INHERITANCE`.

`null` означает отсутствие ссылки на объект. Вызов метода через `null` вызывает `NullPointerException`; отдельные операторы и проверки `null` имеют свою семантику.

## Инициализация и присваивание

```java
int x = 67;     // значение присвоено сразу
int y;
y = x;          // до использования локальная переменная должна быть инициализирована
```

Для **полей** экземпляра и статических полей Java задаёт значения по умолчанию (например, `0`, `false`, `null`). Для **локальных переменных** такой возможности чтения без явного присваивания нет — компилятор проверяет определённость присваивания (*definite assignment*).

Ключевое слово `final` запрещает повторно присвоить переменной другое значение. Но для ссылочной переменной оно **не делает сам объект неизменяемым**:

```java
final StringBuilder text = new StringBuilder("A");
text.append("B");           // допустимо: переменная не переназначена
// text = new StringBuilder("C"); // ошибка компиляции
```

Если присваивание изменяет тип значения, важно понять [приведение типов и автоматические преобразования](conversions.md). Если ссылка передаётся методу, смотрите [передачу аргументов](parameters.md).

Полезно выполнить [общий пример](../../examples/core/ValuesAndReferencesDemo.java): в нём сравниваются копирование числа, копирование ссылки и изменение объекта. Для воспроизведения нужна только JDK 21.

> [!note]- Углубление: что такое ссылка внутри JVM?
> Спецификация языка задаёт поведение ссылок, но **не обязывает** все JVM представлять их одинаково в памяти. Реализация ссылок, размещение объектов и оптимизации относятся к будущим `JVM-MEMORY` и `JVM-JIT`. Нельзя делать вывод «переменная хранит адрес в 64 бита» как общее правило Java.

> [!note]- Углубление: границы числовых типов
> У целочисленных типов есть фиксированные диапазоны, а переполнение обычно не вызывает исключения. Отдельно потребуется разобрать числовые преобразования, `Math.*Exact`, `BigDecimal`, NaN и бесконечности: `CORE-CONVERSIONS` и будущая `CORE-NUMBERS`.
