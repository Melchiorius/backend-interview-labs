# CORE-TYPES — типы, значения и переменные в Java

**Java 21 · основа Java Core**

## Зачем различать переменную, значение, ссылку и объект

Представим, что метод получает ссылку на объект с настройками. Метод может изменить этот объект так, что изменения будут видны другому коду. Но если метод присвоит своей переменной ссылку на другой объект, переменная вызывающего кода не изменится. Чтобы объяснять такое поведение, нужно точно понимать, **что хранит переменная**.

В Java у каждой переменной есть **тип**, а в каждый момент использования — **значение**. Тип определяет, какие значения разрешено хранить и какие операции допустимы. Java — язык со **статической типизацией**: типы переменных и выражений известны компилятору.

Есть две основные категории типов: **примитивные** и **ссылочные**.

```java
int count = 67;                                  // значение — число 67
StringBuilder first = new StringBuilder("A");   // значение — ссылка на объект
StringBuilder second = first;                   // скопирована ссылка, не объект
second.append("B");                             // изменили общий объект
System.out.println(first);                     // AB

second = new StringBuilder("C");                // переназначили только second
System.out.println(first);                     // AB, ссылка first не изменилась
```

**Присваивание примитива копирует примитивное значение, а присваивание ссылки — значение ссылки.** В последнем случае две переменные могут указывать на один изменяемый объект.

[Запускаемый пример с проверками](../../examples/core/TypesAndVariablesDemo.java) иллюстрирует эту модель, значения по умолчанию, `var`, переполнение и UTF-16. В соседней статье отдельно разобрана [передача аргументов в методы](parameters.md).

## Восемь примитивных типов

| Тип | Разрядность | Диапазон / смысл |
|---|---:|---|
| `byte` | 8 бит | −128…127 |
| `short` | 16 бит | −32 768…32 767 |
| `int` | 32 бита | −2 147 483 648…2 147 483 647 |
| `long` | 64 бита | −2⁶³…2⁶³−1 |
| `char` | 16 бит | 0…65 535; **одна кодовая единица UTF-16** |
| `float` | 32 бита | Число с плавающей точкой, примерно 6–9 значащих десятичных цифр |
| `double` | 64 бита | Число с плавающей точкой, примерно 15–17 значащих десятичных цифр |
| `boolean` | Не задана спецификацией как размер ячейки памяти | Только `true` и `false` |

В Java нет `unsigned int` или `unsigned long` как отдельных примитивных типов. `char` — особый **беззнаковый** целочисленный тип. Для работы с битами и беззнаковым представлением отдельных целых существуют операции и методы JDK, но это не создаёт новый unsigned-примитив.

**Размер типа не равен размеру переменной в памяти.** Например, из «`int` — 32 бита» нельзя заключить, что любая локальная переменная занимает ровно четыре байта стека в конкретной JVM. Внутреннее размещение и оптимизации — другая тема (`JVM-MEMORY`, `JVM-JIT`).

### Переполнение, точность и Unicode

```java
int overflow = Integer.MAX_VALUE + 1;
System.out.println(overflow); // -2147483648

long correct = (long) Integer.MAX_VALUE + 1;
System.out.println(correct);  // 2147483648
```

Обычное целочисленное сложение здесь **не выбрасывает исключение**: результат `int` переполняется. Приведение к `long` **до** сложения меняет тип вычисления и позволяет сохранить результат. Подробнее — [преобразования типов](conversions.md) и будущая `CORE-NUMBERS`.

Для `float` и `double` характерны приближения десятичных дробей, возможны `NaN`, бесконечности и `-0.0`. Их поведение и финансовые вычисления с `BigDecimal` будут разобраны в `CORE-NUMBERS`. Не путайте это с переполнением целочисленного типа.

`char` **не обязательно обозначает один пользовательский символ**:

```java
String symbol = new String(Character.toChars(0x1F600)); // 😀
System.out.println(symbol.length());                           // 2 кодовые единицы UTF-16
System.out.println(symbol.codePointCount(0, symbol.length())); // 1 кодовая точка Unicode
```

Здесь одна кодовая точка представлена парой `char`. Кроме того, одна видимая графема может состоять из нескольких кодовых точек. Строки, UTF-16 и обход кодовых точек подробно разобраны в [CORE-STRINGS](strings.md); работа с байтовыми потоками и кодировками на границе ввода-вывода остаётся будущей темой `IO-BYTES`.

## Литералы: как компилятор понимает записанное число

**Литерал** — запись значения непосредственно в исходном коде. `67` без суффикса — литерал типа `int`, а `67L` — `long`. Для вещественного литерала по умолчанию используется `double`; суффикс `F` задаёт `float`.

```java
int decimal = 67;
int binary = 0b0100_0011;     // 67, основание 2
int hexadecimal = 0x43;       // 67, основание 16
int octal = 0103;             // 67, основание 8 (ведущий 0)
long large = 3_000_000_000L;  // L обязателен для такого десятичного числа
float fraction = 1.5F;
double otherFraction = 1.5;
char letter = 'A';            // одинарные кавычки
String word = "A";           // двойные кавычки: ссылочный тип String
boolean valid = true;
```

Подчёркивания в числовых литералах — разделители разрядов, а не часть значения; они разрешены **между цифрами**, но не произвольно у префиксов и суффиксов. Для `long` лучше писать заглавную `L`: строчную `l` легко перепутать с `1`.

### Частые ошибки компиляции

```java
// long wrong = 2147483648; // ошибка: десятичный int-литерал без L вне специального случая
long ok = 2147483648L;

// float wrongFraction = 1.5; // ошибка: double нельзя неявно сузить до float
float okFraction = 1.5F;

// int wrongOctal = 09; // ошибка: с ведущим 0 запись восьмеричная, цифра 9 недопустима
```

Тонкость: `-2147483648` допустимо как особый случай записи минимального `int` — здесь литерал `2147483648` стоит непосредственно под унарным минусом. Но `2147483648` **сам по себе** не является допустимым положительным значением `int`.

Всё это **правила компиляции**, а не результаты выполнения. Другие важные случаи — сужение константных выражений, преобразования `byte + byte` и выбор перегрузки — рассматриваются в [CORE-CONVERSIONS](conversions.md).

## Ссылочные типы, объекты и `null`

Ссылочные типы включают **классы, интерфейсы, массивы и обобщённые варианты ссылочных типов**. Например, `String`, `StringBuilder`, `int[]` и `List<String>` — ссылочные типы, а `int` — примитив.

```java
CharSequence text = new StringBuilder("Java");
int[] numbers = {67, 68};
String missing = null;
```

Объявленный тип `text` — `CharSequence`, а фактический класс объекта — `StringBuilder`. Через переменную можно обращаться к операциям, допустимым для **её объявленного типа**; при вызове переопределённого метода реализация выбирается по фактическому объекту. Об основных составляющих класса и объекта см. [CORE-CLASSES](classes.md); подробности выбора реализации — в [CORE-INHERITANCE](inheritance.md), тонкости интерфейсных контрактов — в [CORE-INTERFACES](interfaces.md).

У массива — собственный объект. Массив `int[]` содержит примитивные значения, но сама переменная `numbers` содержит **ссылку на массив**. Копирование этой ссылки не копирует элементы массива. Ковариантность, копирование, представление и типизацию массивов раскрывает [CORE-ARRAYS](arrays.md).

`null` означает отсутствие ссылки на объект:

```java
String missing = null;
System.out.println(missing == null); // true
// System.out.println(missing.length()); // NullPointerException
// int impossible = null; // ошибка компиляции
```

Вызов **метода экземпляра** через `null` приводит к `NullPointerException`. В то же время само сравнение с `null` допустимо. Особые нюансы обращения к `static`-членам через выражение и совместимости типов разобраны в [CORE-CLASSES](classes.md), а не превращать это в ошибочное правило «любое обращение через null обязательно падает».

### `==` — две разные ситуации

```java
int a = 67, b = 67;
System.out.println(a == b); // true: сравниваются числовые значения

String first = new String("Java");
String second = new String("Java");
System.out.println(first == second);      // false: два объекта
System.out.println(first.equals(second)); // true: одинаковое содержимое
```

Для совместимых примитивных значений `==` сравнивает значения с учётом применимых преобразований; для двух ссылок — **идентичность объектов**, не содержимое. `equals()` — метод, семантика которого задаётся контрактом класса; подробный разбор — [CORE-EQUALITY](equality.md), а исходное identity-сравнение — в [CORE-OBJECT](object.md).

**Интервью-ловушки:** кэш `Integer` (−128…127), сравнение `Integer == int`, строковые литералы, String Pool и `intern()` объясняются в [CORE-CONVERSIONS](conversions.md). Не пытайтесь вывести поведение `==` из одного запуска для `Integer`.

## Какие бывают переменные и почему это важно

| Где объявлена переменная | Как получает первое значение | Что важно помнить |
|---|---|---|
| Поле объекта | Значение по умолчанию, затем объявленные инициализаторы / конструктор | Каждый объект хранит собственное состояние экземпляра |
| `static`-поле класса | Значение по умолчанию при подготовке класса, затем инициализация класса | Поле принадлежит классу, не каждому объекту отдельно |
| Элемент массива | Значение по умолчанию при создании массива | `new int[2]` содержит два нуля |
| Локальная переменная | До чтения должно быть **доказуемое присваивание** | Компилятор запрещает использовать неопределённое значение |
| Параметр метода/конструктора | Получает значение переданного аргумента | Независимая локальная переменная вызова: см. [CORE-PARAMS](parameters.md) |

У спецификации есть и другие категории переменных (например, параметры `catch`, ресурсы и компоненты pattern matching). Они не все требуют отдельной статьи о типах; для binding variables и их flow scope есть отдельная [CORE-PATTERNS](patterns.md), а сами переменные здесь нужны лишь как контекст.

```java
class Counter {
    static int total; // по умолчанию 0
    int value;        // у каждого экземпляра по умолчанию 0

    void update(int value) {
        this.value = value; // поле объекта, а value — параметр метода
        int next;           // пока ничего читать нельзя
        next = value + 1;   // после присваивания читать можно
    }
}

int[] numbers = new int[2]; // numbers[0] == 0, numbers[1] == 0
String[] names = new String[2]; // names[0] == null
```

**Область видимости** определяет, где имя доступно в исходном коде; **время жизни объекта** — другой вопрос. Локальное имя из блока недоступно вне этого блока, но объект, ссылку на который сохраняют где-то ещё, может продолжить существование. Вопросы про достижимость и сборку мусора — будущая `JVM-MEMORY`.

```java
{
    int inside = 67;
    System.out.println(inside); // допустимо
}
// System.out.println(inside); // ошибка: имя вне своей области видимости
```

## `var`: тип выводится, но не меняется

В Java 21 `var` позволяет компилятору **вывести тип локальной переменной из инициализатора**. Это **не динамическая типизация** и не переменная «любого типа».

```java
var count = 67;                      // фактически int
var builder = new StringBuilder("A"); // фактически StringBuilder
builder.append("B");
// count = "text";                   // ошибка: count имеет тип int
// var unknown = null;               // ошибка: невозможно вывести тип из null
// var absent;                       // ошибка: нет инициализатора
```

`var` нельзя использовать для объявления **полей** и обычных формальных параметров методов. В Java 21 `var` также допускается в некоторых объявлениях **параметров лямбд**, а его ограничения разобраны в [CORE-FUNCTIONS](functions.md). Удачное применение `var` делает тип понятным из выражения, а не скрывает его от читателя.

## `final`: значение нельзя переназначить, объект может меняться

```java
final int limit = 67;
// limit = 68; // ошибка компиляции

final StringBuilder message = new StringBuilder("A");
message.append("B");             // допустимо: объект изменился
// message = new StringBuilder("C"); // ошибка: нельзя переназначить переменную

final int computed;
computed = 67;                  // допустимо: первое присваивание
// computed = 68;               // ошибка: второе присваивание
```

У `final` для **переменной** смысл один: после допустимого присваивания нельзя присвоить ей другое значение. Это не обещание, что ссылочный объект неизменяем. `final` у **метода** и **класса** означает другое (запрет переопределения и наследования соответственно): см. [CORE-CLASSES](classes.md) и [CORE-INHERITANCE](inheritance.md). Отдельная [CORE-IMMUTABLE](immutability.md) объясняет наблюдаемую неизменяемость, владение состоянием и защитное копирование.

| Вопрос | Где находится объяснение |
|---|---|
| Почему `int[]` — ссылочный тип, хотя его элементы — `int`? | Ссылочные типы и массивы |
| Почему `long x = 2147483648;` не компилируется, а `2147483648L` — да? | Литералы и правило типа выражения |
| Какие значения имеют поля и массивы до явной инициализации? А локальные переменные? | Категории переменных и definite assignment |
| Почему `var x = 67` не позволяет присвоить строку? | Вывод локального типа |
| Почему `final StringBuilder` можно изменить методом `append()`? | Различие переменной и объекта |
| Почему `Integer.MAX_VALUE + 1` отрицателен? | Переполнение и тип вычисления |
| Почему `"😀".length()` может вернуть 2? | Кодовые единицы UTF-16 |
