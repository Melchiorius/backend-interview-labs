# CORE-TYPES — типы, значения и переменные в Java

**Java 21 · основа Java Core**

## Зачем различать переменную, значение, ссылку и объект

Представим, что метод получает ссылку на объект с настройками. Метод может изменить этот объект так, что изменения будут видны другому коду. Но если метод присвоит своей переменной ссылку на другой объект, переменная вызывающего кода не изменится. Чтобы объяснять такое поведение, нужно точно понимать, **что хранит переменная**.

В Java у каждой переменной есть **тип**, а в каждый момент использования — **значение**. Тип определяет, какие значения разрешено хранить и какие операции допустимы. Java — язык со **статической типизацией**: типы переменных и выражений известны компилятору.

Есть две основные категории типов: **примитивные** и **ссылочные**.

```java
int count = 67;                                  // значение — число 67
StringBuilder first = new StringBuilder("A");   // значение — ссылка на объект
StringBuilder second = first;                   // скопирована ссылка, не объект
second.append("B");                             // изменили общий объект
System.out.println(first);                     // AB

second = new StringBuilder("C");                // переназначили только second
System.out.println(first);                     // AB, ссылка first не изменилась
```

**Присваивание примитива копирует примитивное значение, а присваивание ссылки — значение ссылки.** В последнем случае две переменные могут указывать на один изменяемый объект.

[Запускаемый пример с проверками](../../examples/core/TypesAndVariablesDemo.java) иллюстрирует эту модель, значения по умолчанию, `var`, переполнение и UTF-16. В соседней статье отдельно разобрана [передача аргументов в методы](parameters.md).

## Восемь примитивных типов

| Тип | Разрядность | Диапазон / смысл |
|---|---:|---|
| `byte` | 8 бит | −128…127 |
| `short` | 16 бит | −32 768…32 767 |
| `int` | 32 бита | −2 147 483 648…2 147 483 647 |
| `long` | 64 бита | −2⁶³…2⁶³−1 |
| `char` | 16 бит | 0…65 535; **одна кодовая единица UTF-16** |
| `float` | 32 бита | IEEE 754 binary32; точность нормальных значений — 24 бита значащей части |
| `double` | 64 бита | IEEE 754 binary64; точность нормальных значений — 53 бита значащей части |
| `boolean` | Не задана спецификацией как размер ячейки памяти | Только `true` и `false` |

`boolean` — логический, а не числовой тип. Преобразование `int` в `boolean` и обратно, даже явное приведение, запрещено; для проверки ненулевого числа используют `if (count != 0)` ([JLS §4.2.5](https://docs.oracle.com/javase/specs/jls/se21/html/jls-4.html#jls-4.2.5)).

В Java нет `unsigned int` или `unsigned long` как отдельных примитивных типов. `char` — особый **беззнаковый** целочисленный тип. Для работы с битами и беззнаковым представлением отдельных целых существуют операции и методы JDK, но это не создаёт новый unsigned-примитив.

**Размер типа не равен размеру переменной в памяти.** Например, из «`int` — 32 бита» нельзя заключить, что любая локальная переменная занимает ровно четыре байта стека в конкретной JVM. Внутреннее размещение и оптимизации — другая тема (`JVM-MEMORY`, `JVM-JIT`).

### Два направления десятичного round-trip

`float` и `double` — двоичные форматы IEEE 754 binary32 и binary64, а не десятичные типы. Значащие десятичные цифры характеризуют точность числа, а не количество знаков после запятой: например, 0,00123456 содержит шесть значащих цифр. Важно различать два направления преобразования с обратным восстановлением (round-trip):

- **Десятичное → двоичное → десятичное (`digits10`).** Если исходное десятичное число имеет не более 6 значащих цифр для `float` или 15 для `double`, находится в диапазоне, где сохраняется относительная точность нормальных чисел без переполнения, и оба преобразования выполняются с округлением к ближайшему, его можно восстановить как десятичное число, округлив двоичный результат до исходного количества значащих цифр. Это не означает, что исходная дробь точно представима в двоичном виде.
- **Двоичное → десятичное → двоичное (`max_digits10`).** Для любого конечного ненулевого значения `float` или `double`, включая субнормальные, достаточно корректно округлённой десятичной записи с 9 или 17 значащими цифрами соответственно, чтобы разбор с округлением к ближайшему восстановил исходное двоичное значение. Для знакового нуля требуется сохранить знак в записи; эта оценка не относится к `NaN` и его битовым представлениям. `Float.toString` и `Double.toString` выбирают запись по правилам API так, чтобы обратный разбор восстановил исходное конечное значение; часто достаточно меньшего числа цифр.

Эти оценки следуют из точности двоичных форматов: `p` — число двоичных разрядов значащей части, включая неявный старший единичный бит нормального числа. Для binary32 `p = 24`, для binary64 `p = 53`; `digits10 = floor((p − 1) × log10 2)` даёт 6/15, а `max_digits10 = ceil(1 + p × log10 2)` — 9/17. Это общепринятые численные обозначения, а не имена Java API.

Гарантия 6/15 не распространяется на любой порядок величины. В области субнормальных (subnormal) значений относительная точность постепенно снижается; около границ диапазона преобразование может дать ноль или бесконечность. В Java 21 при округлении к ближайшему и равной дистанции выбирается значение с нулевым младшим битом значащей части (`roundTiesToEven`). Непосредственно выше `2^24` в `float` следующее представимое число равно `2^24 + 2`, а выше `2^53` в `double` — `2^53 + 2`. При сложении в соответствующем вещественном типе точная математическая сумма с единицей лежит посередине между двумя представимыми значениями; округление выбирает исходную степень двойки. Непосредственно ниже этих степеней двойки шаг равен единице, а не двум.

```java
float fromSix = Float.parseFloat("1.23456");
double fromFifteen = Double.parseDouble("1.23456789012345");
System.out.println(String.format(java.util.Locale.ROOT, "%.6g", fromSix));        // 1.23456
System.out.println(String.format(java.util.Locale.ROOT, "%.15g", fromFifteen)); // 1.23456789012345

float nextFloat = Math.nextUp(1.0f);
String floatText = String.format(java.util.Locale.ROOT, "%.9g", nextFloat); // 1.00000012
double nextDouble = Math.nextUp(1.0d);
String doubleText = String.format(java.util.Locale.ROOT, "%.17g", nextDouble); // 1.0000000000000002
System.out.println(Float.parseFloat(floatText) == nextFloat);     // true
System.out.println(Double.parseDouble(doubleText) == nextDouble); // true

float at24 = 16_777_216f;              // 2^24
double at53 = 9_007_199_254_740_992d;  // 2^53
System.out.println(at24 + 1 == at24);   // true
System.out.println(at53 + 1 == at53);   // true
```

Универсального `epsilon` для всех сравнений с плавающей точкой нет: допустимая погрешность зависит от масштаба и задачи. Если требуется точная десятичная арифметика, используйте подходящую модель из [CORE-NUMBERS](numbers.md), а не произвольный допуск. Форматы и субнормальные значения определены в [JLS §4.2.3](https://docs.oracle.com/javase/specs/jls/se21/html/jls-4.html#jls-4.2.3), правила округления — в [JLS §15.4](https://docs.oracle.com/javase/specs/jls/se21/html/jls-15.html#jls-15.4).

### Переполнение, точность и Unicode

```java
int overflow = Integer.MAX_VALUE + 1;
System.out.println(overflow); // -2147483648

long correct = (long) Integer.MAX_VALUE + 1;
System.out.println(correct);  // 2147483648
```

Обычное целочисленное сложение здесь **не выбрасывает исключение**: результат `int` переполняется. Приведение к `long` **до** сложения меняет тип вычисления и позволяет сохранить результат. Подробнее — [преобразования типов](conversions.md) и [CORE-NUMBERS — переполнение и Math.addExact](numbers.md).

Для `float` и `double` характерны приближения десятичных дробей, возможны `NaN`, бесконечности и `-0.0`. Их поведение, три способа создания `BigDecimal`, scale/precision и границы финансовой политики разобраны в [CORE-NUMBERS](numbers.md). Не путайте это с переполнением целочисленного типа.

`char` **не обязательно обозначает один пользовательский символ**:

```java
String symbol = new String(Character.toChars(0x1F600)); // 😀
System.out.println(symbol.length());                           // 2 кодовые единицы UTF-16
System.out.println(symbol.codePointCount(0, symbol.length())); // 1 кодовая точка Unicode
```

Здесь одна кодовая точка представлена парой `char`. Кроме того, одна видимая графема может состоять из нескольких кодовых точек. Сам `char` может содержать и изолированную суррогатную кодовую единицу: тип не проверяет, образует ли она корректную пару UTF-16. `String.codePointCount` учитывает такую единицу как один элемент подсчёта, но не проверяет корректность UTF-16 и не считает графемы:

```java
String loneSurrogate = "\uD800"; // изолированный старший суррогат
System.out.println(loneSurrogate.length()); // 1 кодовая единица UTF-16
System.out.println(loneSurrogate.codePointCount(0, loneSurrogate.length())); // 1
```

Строки, UTF-16 и обход кодовых точек подробно разобраны в [CORE-STRINGS](strings.md); работа с байтовыми потоками и кодировками на границе ввода-вывода остаётся будущей темой `IO-BYTES` ([JLS §3.1](https://docs.oracle.com/javase/specs/jls/se21/html/jls-3.html#jls-3.1), [String.codePointCount](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/String.html#codePointCount%28int%2Cint%29)).

## Литералы: как компилятор понимает записанное число

**Литерал** — запись значения непосредственно в исходном коде. `67` без суффикса — литерал типа `int`, а `67L` — `long`. Для вещественного литерала по умолчанию используется `double`; суффикс `F` задаёт `float`.

```java
int decimal = 67;
int binary = 0b0100_0011;     // 67, основание 2
int hexadecimal = 0x43;       // 67, основание 16
int octal = 0103;             // 67, основание 8 (ведущий 0)
long large = 3_000_000_000L;  // L обязателен для такого десятичного числа
float fraction = 1.5F;
double otherFraction = 1.5;
char letter = 'A';            // одинарные кавычки
String word = "A";           // двойные кавычки: ссылочный тип String
boolean valid = true;
```

Подчёркивания в числовых литералах — разделители разрядов, а не часть значения; они разрешены **между цифрами**, но не произвольно у префиксов и суффиксов. Для `long` лучше писать заглавную `L`: строчную `l` легко перепутать с `1`.

### Частые ошибки компиляции

```java
// long wrong = 2147483648; // ошибка: десятичный int-литерал без L вне специального случая
long ok = 2147483648L;

// float wrongFraction = 1.5; // ошибка: double нельзя неявно сузить до float
float okFraction = 1.5F;

// int wrongOctal = 09; // ошибка: с ведущим 0 запись восьмеричная, цифра 9 недопустима
```

Тонкость: `-2147483648` допустимо как особый случай записи минимального `int` — здесь литерал `2147483648` стоит непосредственно под унарным минусом. Но `2147483648` **сам по себе** не является допустимым положительным значением `int`.

### Знаковые значения в шестнадцатеричных, восьмеричных и двоичных литералах

Для недесятичных целочисленных литералов без суффикса `L` используется 32-битный тип `int`, с суффиксом `L` — 64-битный `long`. Их значащие биты интерпретируются как знаковое значение в дополнительном коде. Поэтому `0xffff_ffff` — это `int` со значением `-1`. При расширении такого `int` до `long` знак сохраняется (sign extension), тогда как суффикс `L` задаёт 64-битный тип самому литералу:

```java
int allBits = 0xffff_ffff;            // -1
long signExtended = allBits;          // -1L: знаковое расширение
long positive = 0xffff_ffffL;         // 4294967295L
long minHex = 0x8000_0000_0000_0000L; // Long.MIN_VALUE
long minDecimal = -9_223_372_036_854_775_808L; // тот же Long.MIN_VALUE

int octalSeparated = 0_103;           // допустимо: восьмеричное 67
// int badHex = 0x_43;                // ошибка: подчёркивание после префикса
// int badTail = 67_;                 // ошибка: подчёркивание в конце
```

Здесь `L` меняет тип и ширину литерала, а не превращает `int` в беззнаковый тип. Правила разрядности, знакового представления и подчёркиваний заданы в [JLS §3.10.1](https://docs.oracle.com/javase/specs/jls/se21/html/jls-3.html#jls-3.10.1).

Всё это **правила компиляции**, а не результаты выполнения. Другие важные случаи — сужение константных выражений, преобразования `byte + byte` и выбор перегрузки — рассматриваются в [CORE-CONVERSIONS](conversions.md).

## Ссылочные типы, объекты и `null`

JLS выделяет четыре формы ссылочных типов: **классы, интерфейсы, переменные типов и массивы**. Параметризованный тип вроде `List<String>` — это тип интерфейса с аргументами типа, а не отдельная пятая категория. Например, `String`, `StringBuilder`, `int[]`, `List<String>` и переменная типа `T` являются ссылочными типами, а `int` — примитивным ([JLS §4.3–4.5](https://docs.oracle.com/javase/specs/jls/se21/html/jls-4.html#jls-4.3)). Подробнее о переменных и аргументах типов — [CORE-GENERICS](generics.md).

`null` имеет специальный тип без имени: нельзя объявить переменную этого типа или привести выражение к этому типу; единственное его значение — null-ссылка, которую можно присвоить любой ссылочной переменной. Это не третья категория объявляемых типов ([JLS §4.1](https://docs.oracle.com/javase/specs/jls/se21/html/jls-4.html#jls-4.1)).

`void` — не девятый примитивный тип: в объявлении метода это ключевое слово, указывающее на отсутствие возвращаемого значения ([JLS §8.4.5](https://docs.oracle.com/javase/specs/jls/se21/html/jls-8.html#jls-8.4.5)). `java.lang.Void` — отдельный `final`-класс-заполнитель с закрытым конструктором для представления `void` в API; это не обёртка с экземплярами значения `void` ([Void, Java SE 21 API](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Void.html)).

```java
CharSequence text = new StringBuilder("Java");
int[] numbers = {67, 68};
String missing = null;
```

Объявленный тип `text` — `CharSequence`, а фактический класс объекта — `StringBuilder`. Через переменную можно обращаться к операциям, допустимым для **её объявленного типа**; при вызове переопределённого метода реализация выбирается по фактическому объекту. Об основных составляющих класса и объекта см. [CORE-CLASSES](classes.md); подробности выбора реализации — в [CORE-INHERITANCE](inheritance.md), тонкости интерфейсных контрактов — в [CORE-INTERFACES](interfaces.md).

Массив сам является объектом. Массив `int[]` содержит примитивные значения, но сама переменная `numbers` содержит **ссылку на массив**. Копирование этой ссылки не копирует элементы массива. Ковариантность, копирование, представление и типизацию массивов раскрывает [CORE-ARRAYS](arrays.md).

`null` означает отсутствие ссылки на объект:

```java
String missing = null;
System.out.println(missing == null); // true
// System.out.println(missing.length()); // NullPointerException
// int impossible = null; // ошибка компиляции
```

Вызов **метода экземпляра** через `null` приводит к `NullPointerException`. В то же время само сравнение с `null` допустимо. Особые нюансы обращения к `static`-членам через выражение, в том числе через `null`, разобраны в [CORE-CLASSES](classes.md). Поэтому неверно обобщать это до правила «любое обращение через null обязательно падает».

### `==` — две разные ситуации

```java
int a = 67, b = 67;
System.out.println(a == b); // true: сравниваются числовые значения

String first = new String("Java");
String second = new String("Java");
System.out.println(first == second);      // false: два объекта
System.out.println(first.equals(second)); // true: одинаковое содержимое
```

Для совместимых примитивных значений `==` сравнивает значения с учётом применимых преобразований. Для двух операндов ссылочного типа или специального типа `null` оператор проверяет, обозначают ли обе ссылки один объект или обе равны `null`, а не сравнивает содержимое объектов. Сравнение допустимо, если тип хотя бы одного операнда можно привести к типу другого по правилам приведения типов (casting conversion); совпадение статических типов необязательно. Две переменные типов `String` и `Integer` нельзя сравнить напрямую, даже если обе содержат `null`: это ошибка компиляции, а не результат `false`. При сравнении числовой обёртки с числовым примитивом или `Boolean` с `boolean` выполняется распаковка (unboxing); распаковка `null` приводит к `NullPointerException` ([JLS §15.21](https://docs.oracle.com/javase/specs/jls/se21/html/jls-15.html#jls-15.21), [§5.1.8](https://docs.oracle.com/javase/specs/jls/se21/html/jls-5.html#jls-5.1.8)).

```java
String absentText = null;
String anotherText = null;
System.out.println(absentText == anotherText); // true
Integer absentNumber = null;
// System.out.println(absentText == absentNumber); // ошибка компиляции: типы несовместимы
// System.out.println(absentNumber == 0);           // NullPointerException при распаковке

Integer smallA = 127;
Integer smallB = 127;
System.out.println(smallA == smallB); // true: гарантия JLS
Integer outsideA = 128;
Integer outsideB = 128;
// Для outsideA == outsideB переносимой гарантии нет.
```

Для двух преобразований упаковки одного и того же константного выражения типа `int` со значением от −128 до 127 включительно JLS гарантирует идентичность полученных ссылок `Integer`. Для двух упаковок константного `int`-выражения со значением 128 при сравнении ссылок не гарантируется ни `true`, ни `false`. Для неконстантного выражения попадание в этот диапазон само по себе не даёт общей гарантии языка ([JLS §5.1.7](https://docs.oracle.com/javase/specs/jls/se21/html/jls-5.html#jls-5.1.7)). Полный перечень случаев, включая `boolean`, `char` и `long`, и отдельный контракт `Integer.valueOf(int)` разобраны в [CORE-CONVERSIONS](conversions.md). `equals()` — метод, семантика которого задаётся контрактом класса; подробный разбор — [CORE-EQUALITY](equality.md), а сравнение идентичности — в [CORE-OBJECT](object.md).

**Интервью-ловушки:** сравнение `Integer == int`, строковые литералы, String Pool и `intern()` дополнительно разобраны в [CORE-CONVERSIONS](conversions.md). Не переносите наблюдаемую идентичность ссылок `Integer` за пределы условий гарантии JLS и не используйте `==` вместо сравнения числовых значений двух обёрток.

## Какие бывают переменные и почему это важно

| Где объявлена переменная | Как получает первое значение | Что важно помнить |
|---|---|---|
| Поле объекта | Значение по умолчанию, затем объявленные инициализаторы / конструктор | Каждый объект хранит собственное состояние экземпляра |
| `static`-поле класса | Значение по умолчанию при подготовке класса, затем инициализация класса | Поле принадлежит классу, не каждому объекту отдельно |
| Элемент массива | Значение по умолчанию при создании массива | `new int[2]` содержит два нуля |
| Локальная переменная | До чтения должно быть **доказуемое присваивание** | Компилятор проверяет, что к месту чтения ей уже присвоено значение (definite assignment) |
| Параметр метода/конструктора | Получает значение переданного аргумента | Независимая локальная переменная вызова: см. [CORE-PARAMS](parameters.md) |

У спецификации есть и другие категории переменных (например, параметры `catch`, ресурсы и переменные, связываемые при сопоставлении с образцом). Последние и их область видимости, зависящая от потока управления, разобраны в [CORE-PATTERNS](patterns.md).

```java
class Counter {
    static int total; // по умолчанию 0
    int value;        // у каждого экземпляра по умолчанию 0

    void update(int value) {
        this.value = value; // поле объекта, а value — параметр метода
        int next;           // next нельзя читать до присваивания
        next = value + 1;   // после присваивания next можно читать
    }
}

int[] numbers = new int[2]; // numbers[0] == 0, numbers[1] == 0
String[] names = new String[2]; // names[0] == null
```

**Область видимости** определяет, где имя доступно в исходном коде; **время жизни объекта** — другой вопрос. Локальное имя из блока недоступно вне этого блока, но объект, ссылку на который сохраняют где-то ещё, может продолжить существование. Вопросы про достижимость и сборку мусора — будущая `JVM-MEMORY`.

```java
{
    int inside = 67;
    System.out.println(inside); // допустимо
}
// System.out.println(inside); // ошибка: имя вне своей области видимости
```

Параметр `value` в `update(int value)` затеняет одноимённое поле; `this.value` явно выбирает поле. Затенение поля параметром или локальной переменной допустимо. В области видимости локальной переменной нельзя объявить другую переменную с тем же именем в обычном вложенном блоке или лямбде. Исключение — новое объявление внутри объявления класса или интерфейса, вложенного в область видимости исходной переменной. **Область видимости** отвечает на вопрос, где доступно имя; **определённое присваивание (definite assignment)** — устанавливает ли компилятор по формальным правилам JLS, что к месту чтения переменной ей уже присвоено значение ([JLS §6.3–6.4](https://docs.oracle.com/javase/specs/jls/se21/html/jls-6.html#jls-6.3), [JLS §16](https://docs.oracle.com/javase/specs/jls/se21/html/jls-16.html)).

```java
boolean condition = true; // не константная переменная: текущее значение само по себе не доказательство
int result;
if (condition) result = 67;
else result = 68;
System.out.println(result); // 67 при condition == true; обе ветви присваивают result

final boolean always = true; // константная переменная
int known;
if (always) known = 67;
System.out.println(known); // допустимо: условие — константное выражение true

// Отдельный отрицательный вариант (без else):
// boolean condition = true;
// int result;
// if (condition) result = 67;
// System.out.println(result); // ошибка компиляции: result может быть не присвоено значение
```

## `var`: тип выводится, но не меняется

В Java 21 в обычном объявлении локальной переменной `var` позволяет компилятору **вывести её статический тип из инициализатора**. Это **не динамическая типизация** и не переменная «любого типа».

```java
var count = 67;                       // фактически int
var builder = new StringBuilder("A"); // фактически StringBuilder
var array = new int[]{67, 68};         // допустимое явное создание массива
builder.append("B");
// count = "text";                    // ошибка: count имеет тип int
// var unknown = null;                // ошибка: невозможно вывести тип из null
// var absent;                        // ошибка: нет инициализатора
// var bareArray = {67, 68};          // ошибка: инициализатор массива без new int[]
// var first = 67, second = 68;       // ошибка: несколько переменных в объявлении
// var values[] = new int[2];         // ошибка: скобки после имени
// var self = (self = 67);            // ошибка: ссылка на переменную в собственном инициализаторе
```

В обычном локальном объявлении с `var` нужна ровно одна переменная с инициализатором; нельзя использовать непосредственный инициализатор массива `{...}`, добавлять `[]` после имени или ссылаться на переменную в её собственном инициализаторе. `new int[]{67, 68}` допустим, потому что это выражение создания массива. В расширенном `for`, например `for (var element : array)`, тип выводится из типа элементов массива или из типа элемента `Iterable`; отдельного инициализатора переменной в заголовке нет. В объявлении нового ресурса `try`-с-ресурсами с `var` нужен инициализатор, а тип ресурса должен удовлетворять требованиям `try`-с-ресурсами. Для полей и обычных параметров методов/конструкторов `var` не допускается ([JLS §14.4.1](https://docs.oracle.com/javase/specs/jls/se21/html/jls-14.html#jls-14.4.1), [§14.14.2](https://docs.oracle.com/javase/specs/jls/se21/html/jls-14.html#jls-14.14.2), [§14.20.3](https://docs.oracle.com/javase/specs/jls/se21/html/jls-14.html#jls-14.20.3)).

Локальное объявление с `var` не задаёт инициализатору целевой тип: выражение рассматривается как самостоятельное (standalone). Поэтому непосредственно записать в качестве инициализатора лямбду или ссылку на метод нельзя. У параметров лямбды с `var` направление вывода другое: их типы определяются целевым функциональным интерфейсом. Если выбран синтаксис с `var`, все параметры должны быть записаны с `var`; формы `(var x, y)` и `(var x, String y)` недопустимы. Нельзя смешивать явно заданные типы с выводимыми, а среди выводимых — простые имена и форму с `var`.

```java
java.util.function.Function<String, Integer> length = (var text) -> text.length();
// var lengthWithoutTarget = (var text) -> text.length(); // ошибка: у лямбды нет целевого типа
// var methodWithoutTarget = String::length; // ошибка: у ссылки на метод нет целевого типа
```

Удачное применение `var` делает тип понятным из выражения, а не скрывает его от читателя. Как явное приведение предоставляет целевой тип лямбде и позволяет вывести тип локальной переменной, показано в [CORE-FUNCTIONS](functions.md). Формальные правила — [JLS §15.13](https://docs.oracle.com/javase/specs/jls/se21/html/jls-15.html#jls-15.13) и [§15.27.1](https://docs.oracle.com/javase/specs/jls/se21/html/jls-15.html#jls-15.27.1).

## `final`: значение нельзя переназначить, объект может меняться

```java
final int limit = 67;
// limit = 67; // ошибка компиляции даже при повторном присваивании того же значения

final StringBuilder message = new StringBuilder("A");
message.append("B");             // допустимо: объект изменился
// message = new StringBuilder("C"); // ошибка: нельзя переназначить переменную

final int computed;
computed = 67;                  // допустимо: первое присваивание
// computed = 67;               // ошибка: второе присваивание даже того же значения
```

Переменной `final` можно присвоить значение **не более одного раза**. Речь о конкретной переменной: например, у каждого экземпляра класса собственное поле, а у каждого вызова метода — собственная локальная переменная. Совпадение нового значения с прежним ничего не меняет. Перед присваиванием переменной, объявленной как `final` без инициализатора (blank `final`), компилятор должен установить по правилам определённой неприсвоенности (definite unassignment), что ей ещё не присвоено значение ([JLS §16](https://docs.oracle.com/javase/specs/jls/se21/html/jls-16.html)). **Константная переменная (constant variable)** — более узкое понятие: это `final`-переменная примитивного типа или `String`, инициализированная константным выражением (constant expression). Поэтому `final StringBuilder` не является константной переменной. **Effectively final** — отдельное свойство не объявленных как `final` локальных переменных и параметров, используемое, в частности, при захвате лямбдами ([JLS §4.12.4](https://docs.oracle.com/javase/specs/jls/se21/html/jls-4.html#jls-4.12.4); см. также [CORE-FUNCTIONS](functions.md)).

Это не обещание, что ссылочный объект неизменяем. `final` у **метода** и **класса** означает другое (запрет переопределения и наследования соответственно): см. [CORE-CLASSES](classes.md) и [CORE-INHERITANCE](inheritance.md). Отдельная [CORE-IMMUTABLE](immutability.md) объясняет наблюдаемую неизменяемость, владение состоянием и защитное копирование.
