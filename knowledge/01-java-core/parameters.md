# CORE-PARAMS — как Java передаёт аргументы в методы

**Java 21 · предпосылки:** [значения и ссылки](types.md), [преобразования](conversions.md)

## Главное правило

**Java всегда передаёт аргументы по значению.** Когда метод вызывается, для каждого параметра создаётся локальная переменная метода. В неё попадает значение соответствующего выражения.

Если аргумент примитивного типа, копируется примитивное значение. Если аргумент ссылочного типа, копируется **значение ссылки** — это не копирование самого объекта и не передача переменной вызывающего кода «по ссылке».

## Примитив: две независимые переменные

```java
static void change(int number) {
    number = 100;
}

int value = 67;
change(value);
System.out.println(value); // 67
```

Метод переназначает только собственную переменную `number`. В `value` вызывающего кода остаётся `67`.

## Ссылка: один общий объект, но две переменные

```java
static void append(StringBuilder target) {
    target.append("B");
}

StringBuilder text = new StringBuilder("A");
append(text);
System.out.println(text); // "AB"
```

При входе в метод переменные `text` и `target` содержат ссылки на **один и тот же объект**. Поэтому изменение объекта через `target.append()` видно и при обращении к нему через `text`.

Но если внутри метода **переназначить сам параметр**, переменная вызывающего кода не изменится:

```java
static void replace(StringBuilder target) {
    target = new StringBuilder("C");
    target.append("D");
}

StringBuilder text = new StringBuilder("A");
replace(text);
System.out.println(text); // "A"
```

После присваивания `target = ...` метод работает с другим объектом. Переменная `text` всё ещё содержит старую ссылку.

## Что означает слово «изменить»

Не смешивайте два разных действия:

| Действие | Меняет переменную вызывающего кода? | Может менять общий объект? |
|---|---|---|
| `parameter = new Object()` | Нет | Не само по себе |
| `parameter.setValue(...)` | Нет | Да, если метод изменяет объект |
| `parameter = null` | Нет | Нет |

`final` у параметра запрещает **переназначить параметр** внутри метода, но не запрещает менять объект через его методы. Сравните с [правилом о `final` у ссылочных переменных](types.md).

## Как вернуть новое значение вызывающему коду

Если требуется именно замена ссылки или числа, верните новое значение явно:

```java
static int increase(int number) {
    return number + 1;
}

int count = 67;
count = increase(count);  // теперь 68
```

Это делает изменение явным. Если необходима работа с изменяемым объектом, обдумайте его жизненный цикл и договорённость о том, кто его меняет.

## Воспроизводимый пример

В [ValuesAndReferencesDemo.java](../../examples/core/ValuesAndReferencesDemo.java) показаны сразу три случая: примитивное значение, изменение общего объекта и переназначение локального параметра. Запуск из корня репозитория:

```powershell
java examples/core/ValuesAndReferencesDemo.java
```

Нужен JDK 21. Пример использует режим запуска Java из исходного файла (source-file mode); отдельная настройка Gradle не требуется.

> [!note]- Углубление: объекты, неизменяемость и многопоточность
> То, что две переменные ссылаются на один объект, само по себе **не гарантирует** безопасного совместного изменения этого объекта из разных потоков. Продолжение — `CON-RACE`, `CON-JMM`, а для проектирования объектов — `CORE-IMMUTABLE`.

> [!note]- Углубление: передача аргумента и overload
> Аргумент сначала вычисляется, затем его значение используется для инициализации параметра. Передачу могут сопровождать преобразования, разрешённые выбранным методом. Выбор перегрузки — отдельный вопрос, затронутый в [преобразованиях](conversions.md).
