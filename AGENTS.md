# Правила работы с репозиторием

## Назначение

Репозиторий предназначен для глубокой подготовки к собеседованиям Java Backend. Материалы должны помогать понимать устройство платформы и аргументированно обсуждать инженерные решения, а не только воспроизводить определения.

## Язык и стиль

- Основной язык обсуждений и документации — русский.
- Имена API, классов, методов, параметров JVM и общепринятые термины не переводить искусственно.
- Объяснять причинно-следственные связи. Не подменять объяснение перечнем терминов.
- Использовать конкретные примеры. Для условных числовых примеров предпочитать число 67.
- Не упрощать техническую точность ради эффектной формулировки.

## Требования к техническим утверждениям

- Разделять гарантии Java Language Specification, JVM Specification, Java API и детали конкретной реализации.
- Указывать версию Java, если поведение зависит от версии.
- Не выдавать типичное поведение HotSpot или OpenJDK за обязательную гарантию языка.
- Для спорных и меняющихся деталей проверять первичную документацию.
- Если утверждение не подтверждено, явно обозначать неопределённость.
- Не придумывать результаты benchmark, тестов или экспериментов.

## Требования к примерам кода

- Базовая версия — Java 21.
- Код должен быть компилируемым и иметь понятный способ запуска.
- Для нетривиальных гарантий добавлять тесты или воспроизводимый эксперимент.
- Не использовать Thread.sleep как средство синхронизации тестов, если задача не состоит именно в демонстрации временного поведения.
- Для многопоточных примеров объяснять, что именно гарантируется, а что остаётся недетерминированным.
- Не скрывать ошибки обработки исключений, отмены, прерывания и освобождения ресурсов.
- Не добавлять библиотеки без обоснованной необходимости.

## Формат изучения темы

1. Постановка проблемы и мотивация.
2. Ментальная модель и основные понятия.
3. Подробное объяснение механизма.
4. Полный разобранный пример.
5. Гарантии и ограничения.
6. Ошибочные сценарии и контрпримеры.
7. Сравнение альтернатив и компромиссы.
8. Практическая лабораторная работа.
9. Вопросы для проверки глубины понимания.

Не начинать сложную тему с блица или требования написать весь код с нуля. Сначала дать связную теорию и готовый пример, затем разбирать его по частям и постепенно переходить к самостоятельной практике.

## Работа с Git

- Не работать непосредственно в main, если задача предполагает изменение файлов.
- Создавать отдельную ветку на логическую задачу.
- Делать небольшие, содержательные коммиты.
- Перед PR запускать релевантные тесты и указывать фактический результат.
- В PR описывать цель, ключевые изменения, проверку и известные ограничения.
- Не выполнять merge без прямого разрешения владельца.
- Не переписывать историю общей ветки и не применять force push без отдельного согласования.

## Границы

- Не превращать лабораторию в набор случайных задач.
- Не добавлять Spring Boot, базы данных, брокеры и Docker только ради технологического списка.
- Не смешивать спецификацию платформы, детали реализации и собственные предположения.
- Не считать успешную компиляцию доказательством корректности многопоточного поведения.
